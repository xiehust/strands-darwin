## Primary-source follow-up

### U03 / U09 — Regenerate candidates from each observation

The [pinned Ultrafast README](https://github.com/browser-use/jev-ultrafast/blob/1231850a0bf1a0c0341fe408ef1668dbbfdfac46/README.md)
describes a fresh indexed element table and compatible operation/target choices.
Target questions are asked speculatively; only the target matching the selected
operation is consumed. A separate small model supplies text for typing. This is
a concrete instance of the existing [conditional fan-out pattern](implementation-patterns.md).
Its flight-search timing is an author demo, not a general browser success rate.
No browser session was launched for this follow-up.

### U08 — Better action interfaces, not just a faster selector

[WindTunnel's leaderboard](https://webmcp.com/benchmark) and
[pinned release provenance](https://github.com/nekuda-ai/WindTunnel/blob/5ca8644e23826ebb30108e7bad240b61043bfe67/results/2026-09-18-jev-mercury/PROVENANCE.md)
report 49 tasks with three attempts each. WebMCP + Jev + Mercury passed
**141/147 attempts** and solved **49/49 tasks**, where solved means a majority
of three attempts. The DOM configuration passed **76/147** and solved **25/49**.
These are different complete harnesses, not an isolated interface ablation.

The reported WebMCP median model cost is $0.001063960 versus DOM $0.000777958:
the WebMCP median is higher. Conversely, summed known costs of scored attempts
are $0.201557376 versus $0.245387386, explaining the roughly 18% aggregate saving.
Unknown-usage reserves and recovery requests are accounted separately. Do not
mix totals, medians and cost per successful task.

Jev chooses actions; Mercury generates arguments, field values and final answers.
The [reproduction guide](https://github.com/nekuda-ai/WindTunnel/blob/5ca8644e23826ebb30108e7bad240b61043bfe67/experiments/jev/README.md)
describes frozen sources and paid-run prerequisites. We inspected documentation,
not all traces or executable implementations, and did not reproduce the result.

**Adaptation:** expose meaningful actions such as `search_catalog` or
`reserve_available_slot`, with schemas and receipts, rather than asking the
selector to rediscover a long click sequence. Do not invent website APIs: use
actually available capabilities and fall back to observed UI actions when needed.
Generation and execution remain separate from selection.

### U13 — Customize the cost of acting now versus waiting

The [pinned README](https://github.com/kunchenguid/compact-adviser/blob/b2a27b59ce86af4dc8fb5141e169bfbed1e68cee/README.md)
documents two judgments—completion and work shape—combined in code, with a
threshold that relaxes as the context fills. Its current documentation includes
Pi/Claude opt-in automatic compaction and Codex/Grok hint-only support; this is
upstream behavior, not functionality implemented by our skill.

[Judge profiles](https://github.com/kunchenguid/compact-adviser/blob/b2a27b59ce86af4dc8fb5141e169bfbed1e68cee/docs/judge-profiles.md)
let users change question text, the coordination weight and the usage/floor
schedule. The composed score is a policy signal, not automatically a calibrated
probability of safe compaction. A profile change invalidates pending advice and
does not grant automatic-mode consent.

The supplied post describes tuning on 40 sessions. Current README and
[measured-results notes](https://github.com/kunchenguid/compact-adviser/blob/b2a27b59ce86af4dc8fb5141e169bfbed1e68cee/packages/pi-extension/eval/measured-results.md)
describe different evaluation slices; private transcripts/labels are not released.
Do not combine their denominators or treat prompt hillclimbing as independent
held-out validation. The notes distinguish phase completion from whether later
work still needs older details. Good hint timing alone does not prove information
survives compaction.

**Adaptation:** let the host's current resource pressure change the cost of
false triggers versus missed opportunities; do not falsify the model's returned
probability. Start advisory, preserve pending tasks/artifacts and test downstream
continuations before enabling any host-supported automatic action.

### U05 / U15 — Deadline handling and receipts are separate from decisions

The [pinned trader README](https://github.com/jarrodwatts/jev-trader/blob/b587759e459ea049590102e54a0b07800864cdc3/README.md)
documents a default mock model and dry-run behavior without a private key; the
listed deployment is described as mock/dry-run. This does not disprove the
author's separate live-demo claim, but a running dashboard alone cannot verify it.
The described loop skips late decisions, and distinguishes an order intent,
placement/reversion receipt and later fill. Position limits may change what is
executed while retaining the original model output.

**Adaptation:** reuse deadline checks, one-in-flight scheduling, stale-decision
rejection and intent-versus-receipt accounting in simulations, games and job
schedulers. Do not adopt automatic opposite-side execution as a generic fallback.
This is not investment guidance, profit evidence or authorization to trade.

### U29 — Examples as editable programs

The [pinned Jev Explained README](https://github.com/davila7/jev-explained/blob/ef7105e3953ffd5bf5247cf996f52cebca250603/README.md)

the playground's TypeSafe/Vercel endpoint or key-storage design.

## New ways to compose the ideas

These are **our proposed adaptations** of the supplied descriptions, not newly
verified deployments:

- **Strategic/tactical loop (U10, U26):** a reasoning model chooses a short
  subgoal; Jev chooses legal local actions. Refresh the strategy when the subgoal
  completes, assumptions change or progress stalls. A fast wrong action repeated
  many times is not successful long-horizon planning.
- **Primitive-level assistance (U12, U23):** use a decision only inside an
  existing `observe`, `act` or extraction operation. The caller can remain human
  or deterministic; adding Jev need not create an autonomous agent.
- **Conversation choreography (U28):** give each bot a role and current speaking
  eligibility; select the next speaker, response type or pause. Code handles
  turn budgets and prevents a conversation from looping indefinitely.
- **Expressive presentation (U28):** classify a fictional utterance's intended
  delivery into user-defined style labels and map them to permitted TTS presets.
  Keep neutral/unclear fallback and smoothing. This controls presentation; it is
  not evidence about a person's inner emotion or a psychological diagnosis.
- **Question compilation:** a related [OpenRouter example](https://openrouter.ai/labs/jev/compile)
  uses a generative model to translate a classification prompt into typed
  questions, then applies them across records. Review the resulting rubric,
  scope every question to an explicit row ID and version it before reuse. This
  helps customization without requiring users to hand-author every API request.

shapes. U07's roundup, U17's exact Ori experiment, and the truncated U18/U22
articles remain follow-up leads, not silently completed research.
