# Design — Codex-compatible portable hooks

## Architecture and boundaries

Add a second, explicitly identified hook dialect rather than changing the meaning of Darwin's existing hook files. Native `hooks/*.json`, legacy `.darwin/hooks.json`, and config-embedded hooks remain `ToolHooksConfig` with glob matchers and the established execution behavior. Only direct global/project `.agents/hooks.json` files use the documented Codex JSON shape and regex matcher contract.

`runtime.ts` remains the only main `Agent` constructor and `SubagentTool` remains the only child constructor. The adapter uses existing Strands extension points and driver-owned boundaries; it does not wrap or fork the SDK loop.

### Source order

For each `.agents` layer, the portable file is ordered before that layer's lexical native `hooks/*.json` sources. The complete Pre/setup order is:

1. global `.agents/hooks.json` (Codex dialect)
2. global `.agents/hooks/*.json` (native dialect)
3. global `.darwin` native sources/fallback
4. project `.agents/hooks.json` (Codex dialect)
5. project `.agents/hooks/*.json` (native dialect)
6. project `.darwin` native sources/fallback

Post/teardown order is the exact reverse at source granularity. Other Codex lifecycle events use setup order. `.codex/hooks.json` is never discovered, preventing duplicate execution when a portability generator writes both files.

The loaded policy carries native and Codex definitions separately, with source paths attached to every Codex handler. This preserves dialect-specific matching, payloads, output parsing, error messages, and diagnostics rather than converting one contract into a lossy common shape.

## Modules and ownership

### `src/hooks/codex-hooks.ts`

Own the Codex-dialect types and strict decoder:

- all eleven event names;
- event groups and regex matcher compilation;
- command handler fields (`command`, `commandWindows`, `timeout`, `statusMessage`, `additionalContextLimit`, `async`);
- rejection of unsupported handler types and background execution;
- source-aware `ConfigError` paths;
- match-all normalization for omitted matcher, `""`, and `"*"`;
- event-specific input and output types/normalization.

The decoder accepts inert `description` and `statusMessage`. It validates `additionalContextLimit` and converts the approximate token limit into a conservative bounded character/byte budget under a lower global hard cap. It does not create spill files because hook-generated bytes must not create a second durable context channel.

### `src/hooks/hook-process.ts`

Extract the reusable bounded process-group runner currently duplicated between tool and lifecycle hooks. One implementation owns:

- `/bin/sh -c` on POSIX and `commandWindows` selection on Windows;
- project-root cwd and inherited environment;
- one bounded JSON stdin payload;
- bounded stdout/stderr capture;
- per-handler timeout with a global maximum;
- caller cancellation;
- TERM → bounded KILL process-group cleanup;
- active-process tracking and `cancel()`/`close()` for runtime retirement and unwind.

Native hook behavior remains unchanged when moved onto this primitive: native Pre still fails closed, native Post still observes, and native lifecycle hooks remain non-blocking/output-free.

### `src/hooks/codex-hook-runner.ts`

Own one runtime's portable hook state and pending model context. It provides narrow methods named by lifecycle boundary rather than exposing raw config to drivers:

- `sessionStart(source)` / `sessionEnd(reason)`
- `userPromptSubmit(prompt)`
- `preToolUse(event)` / `postToolUse(event)`
- `permissionRequest(source)`
- `preCompact(trigger)` / `postCompact(trigger)`
- `subagentStart(agent)` / `subagentStop(result)`
- `stop(outcome)`
- `takePendingParentContext()`
- `cancel()` / `close()`

A shared decoder parses command output once. Event adapters then accept only their supported projection. Unsupported controlling fields become bounded diagnostics/problems and never silently gain a weaker controlling meaning.

The runner serializes matching handlers in deterministic source/group/handler order. This deliberately preserves Darwin's wrapper policy and differs from Codex's concurrent matching-handler execution; the user guide calls out the difference.

## Matching and tool aliases

Codex matchers compile as regular expressions. Native Darwin matchers remain wildcard globs.

Tool events match against the actual Darwin registered tool name plus safe compatibility aliases:

- `bash` also offers `Bash`;
- mutating `fileEditor` operations offer `apply_patch`, `Edit`, and `Write` in addition to `fileEditor`;
- read-only `fileEditor` operations remain `fileEditor` only;
- other local and MCP tools use their actual registered Darwin names.

The payload's `tool_name` remains the actual Darwin name so the adapter never lies about the invoked API. `tool_input` remains the actual Darwin argument object; aliases affect matching only.

Subagent matchers run against the selected Darwin definition name. Session/compact matchers use the documented source/trigger strings. `UserPromptSubmit` and `Stop` ignore matcher, matching Codex release behavior.

## Common payload projection

Every portable command receives truthful available common fields:

```json
{
  "session_id": "session-…",
  "cwd": "/absolute/project/root",
  "hook_event_name": "UserPromptSubmit",
  "model": "provider model id",
  "permission_mode": "default"
}
```

`transcript_path` and `turn_id` are omitted because Darwin has no Codex transcript/wire identifier. Permission modes map only when semantics are truthful: `default → default`, `plan → plan`, and `yolo → bypassPermissions`; Darwin `auto` is omitted rather than mislabeled.

Payloads are serialized through one bounded encoder. Tool results, assistant text, reasons, and prompts have per-field caps inside the total payload cap. No payload contains reasoning, a child transcript path, image bytes, offloaded bytes, or trajectory file contents.

## Event behavior matrix

| Event | Darwin seam | Awaited behavior | Supported output | Deliberate limitation |
|---|---|---|---|---|
| `SessionStart` | after restore/current prompt refresh in `AgentRuntime.create` | yes, before runtime is returned | plain stdout or `additionalContext` staged for first parent invocation | fires for initial `startup`, explicit resume, and `/clear`; rewind emits no false Codex source; does not rewrite system/history |
| `UserPromptSubmit` | start of `AgentRuntime.send`, before rewind capture and trajectory begin | yes | plain/context injection; `decision:block` or exit 2 refuses locally | no prompt rewrite; literal user input remains trajectory/memory source |
| `SubagentStart` | after child initialization, before first `invoke` | yes | plain/context injection into only that child task | `continue:false` cannot prevent child startup |
| `PreToolUse` | composed intervention after plan/retry guard, before permission | yes | deny/exit 2, advisory context, `allow + updatedInput` | permission reclassifies final input; no auto-approval |
| `PostToolUse` | existing eligible-call AfterTool seam | yes, in reverse wrapper order | no controlling output; diagnostics only | original result is never replaced/retried/hidden |
| `PermissionRequest` | visible approval publication seam | no | output discarded | cannot allow or deny; Darwin gate remains sole authority |
| `PreCompact` | before explicit `/compact` / headless `compactBefore` | yes | `continue:false` or block refuses that explicit compact | no interception of SDK overflow recovery; trigger is `manual` only |
| `PostCompact` | after successful explicit compact/persist | yes | bounded context staged for next parent invocation | no false `auto` event |
| `SubagentStop` | after child result, before tool callback returns | no | output discarded | no transcript path and no automatic child continuation |
| `Stop` | driver-owned completed/failed/cancelled parent outcome | no | output discarded | no automatic parent continuation and no stream buffering |
| `SessionEnd` | orderly runtime retirement/shutdown | yes under the Codex 3-second maximum | advisory output discarded | best effort only; no crash or idle timer guarantee |

Native `TurnComplete` and native `PermissionRequest` stay byte-for-byte unchanged. Portable `Stop` and portable `PermissionRequest` are additional source-specific projections; they do not replace native events.

## Model-context injection

The runner stores bounded pending parent context from `SessionStart` and `PostCompact`. On an actual parent send, `UserPromptSubmit` runs and its context is appended in deterministic order. The combined context is prepended to the **model-facing invocation text only** using a bounded tagged block. The separate literal `userInput` argument remains the source for trajectory, prompt recall, memory evidence, shell reports, rewind eligibility, and clipboard-image durability.

For multimodal input, only the invocation's text block gains the hook context; the image block is unchanged. No base/system prompt mutation is required, so prompt-cache ordering and resume snapshots remain stable.

`SubagentStart` uses the same bounded tagged projection on the child task passed to `child.invoke()`. It never mutates the child definition, parent transcript, or retained child result.

## Tool policy integration

`ToolHookGate` keeps the enforced order:

```text
plan guard → repeated-failure guard → native/portable Pre → permission(final input)
→ body → portable/native Post → repeated-failure observation
```

Portable `updatedInput` is schema-checked as a replacement object and applied through Strands' sanctioned mutable `BeforeToolCallEvent.toolUse.input` seam. Later hooks and the permission classifier see the transformed input. A hook cannot change the tool name, selected tool, permission mode, or source identity.

Portable Pre launch errors, timeout, invalid output, nonzero exit other than the documented exit-2 denial, or invalid replacement fail closed and deny the tool. Post runtime failures remain observation-only and are surfaced only through bounded diagnostics/startup status, never by replacing the tool result.

## Session and cancellation ownership

The portable runner is constructed before lifecycle execution and passed into the existing intervention and `SubagentTool`. `AgentRuntime` owns it. Startup unwind closes it; turn cancellation cancels turn-scoped commands; `/clear` retires the predecessor and emits one `SessionEnd` before closing predecessor-owned hook processes; final shutdown does the same. A latch guarantees one `SessionEnd` per runtime.

A `/clear` successor receives a `SessionStart(source="clear")`. A resumed process uses `resume`; a fresh process uses `startup`. A rewind successor intentionally emits no Codex `SessionStart`, because Codex's four documented source values contain no truthful branch equivalent.

## Failure and visibility policy

- Parse/read/schema/regex errors in active executable policy are startup `ConfigError`s naming source and field.
- Runtime Pre policy failures deny; UserPromptSubmit exit 2/block refuses; PreCompact block refuses compact.
- Context-producing startup/prompt/child/post-compact hook failures discard that handler's context, continue safely, and surface one bounded problem through existing runtime notices/diagnostics.
- Observation hook failures never alter their owner.
- No raw hook stdout/stderr is printed into Ink or structured stdout. Only bounded refusal/problem text uses existing error/notice channels.
- No hook event or output is added to trajectory schema.

## Verification design

Add focused offline suites rather than mocks of the adapter:

- `spike/verify-codex-hooks.ts`: real temp config files and real child shell commands for decoding, source order, regex/match-all, aliases, payload/output bounds, timeout, process-group cleanup, all eleven events, and unsupported controls.
- Extend `spike/verify-state-layers.ts` for portable-file discovery, native coexistence, duplicate prevention, malformed policy, symlink/read failures, and sensitive path classification.
- Extend tool-hook/retry coverage for final-input permission classification and unchanged plan/retry/Post ordering.
- Extend compact, clear-session, lifecycle, subagent, trajectory, memory, runtime-image, and structured-headless suites only where their boundary is changed.
- Add the focused suite to `pnpm test`; finish with `pnpm typecheck`, `pnpm test`, `git diff --check`, and relevant free PTY scenarios selected after the changed surfaces are known.
