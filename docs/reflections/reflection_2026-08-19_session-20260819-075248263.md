## 4. Improvement findings for darwin

### F1 — A turn-level stream failure costs the whole turn and waits for a human `continue`

- **Evidence:** seq 119 `turnEnded` with `failure: {name: "ModelError", message: "Stream
  ended without completing a message"}` after 678,954 ms, 20 model calls and 30 tool calls,
  with no `agentResultEvent` in turn 1; seq 120 `userInput: "continue"` is the user manually
  restarting the work. Recovery worked (turn 2 picked up exactly where turn 1 died), proving
  the failure was transient and a continuation was sufficient.
- **Root-cause area:** orchestration / execution time (error handling at the runtime layer).
- **Suggestion:** bounded automatic turn resumption for retryable stream failures: when a turn
  throws a `ModelError` of the stream-interrupted kind, the runtime (at the same layer that
  already drains the SER-027 prompt queue through the ordinary `submit()` path — never inside
  the SDK loop) resubmits one continuation prompt, at most once per turn, visibly stated in
  the transcript and recorded honestly as its own turn with its own `turnEnded`. Non-retryable
  failures (auth, validation) keep today's behavior.

### F2 — The bash tool schema invites a wasted call when `command` is sent in `status` mode

- **Evidence:** seq 191/192 (turn 2): the model called `bash` with
  `{"command": "bg-…", "mode": "status", "taskId": "bg-…"}` and was rejected with the zod
  error `"command is not accepted in status mode"`; the corrected retry at seq 194/195 cost an
  extra model call. The model had the right intent (poll a background task) and the right
  taskId — the schema's strictness turned a redundant field into a hard failure.
- **Root-cause area:** tool description (input schema ergonomics).
- **Suggestion:** either tolerate the redundant field (strip/ignore `command` when `mode` is
  `status`/`output`/`stop`, since `taskId` is authoritative there) or state the per-mode field
  matrix explicitly in the bash tool description (`command`: execute/start only; `taskId`:
  status/output/stop only), so the first call is well-formed.

### F3 — Conversation-language vocabulary leaked into English repository artifacts

- **Evidence:** the turn-1 prompt (seq 1) specified the grade levels in Chinese
  (完美/高/中/低) and the session shipped them verbatim into the template, SKILL, spike
  assertion, README and spec; turn 3 (seq 254–290: 9 tool calls, 6 model calls, edits at
  seq 262–283) was spent replacing them in six places with English.
- **Root-cause area:** system prompt (artifact-language guidance).
- **Suggestion:** add one system-prompt line: persistent repository artifacts (docs, code
  identifiers, test assertions) follow the repository's existing language conventions even
  when the conversation is in another language; when the user's spec supplies terms in the
  conversation language, surface the mismatch once instead of silently translating. Note the
  evidence is weak that this was avoidable: the user's own prompt specified the Chinese
  tokens, so turn 3 reads as a requirement refinement at least as much as a darwin defect.
