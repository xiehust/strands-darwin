## 4. Improvement findings for darwin

### F1 — Background supervision still wakes on every output fragment

- **Evidence:** the two long-running workers required 133 and 128 `bash wait` calls respectively (turn 1, seq 153–549 and seq 631–1021), even though supervision only needed incremental progress occasionally and terminal completion. This drove 261 of the turn's 320 bash calls and accompanied a 46-minute turn and 119115765 parent cache-read tokens (seq 1098).
- **Root-cause area:** execution time and token spend
- **Suggestion:** extend background `bash wait` with an explicit terminal-focused mode such as `wakeOnOutput: false`, still bounded by `waitMs`, that advances/aggregates the output cursor but returns only on terminal state, cancellation, shutdown, or timeout. Keep the current output-sensitive behavior as the default for compatibility.

### F2 — A harmless execute-only field makes `bash start` fail closed

- **Evidence:** the launch at turn 1 seq 138 supplied `timeout: 30`; validation rejected the entire call with `timeout is not accepted in start mode` at seq 140, and the same command succeeded once the field was omitted at seq 141–143.
- **Root-cause area:** tool description
- **Suggestion:** make `timeout` harmless when `mode: "start"` by ignoring it, while continuing to document that background lifetime is controlled through `wait`/`stop`. Add schema and regression coverage proving a redundant timeout cannot prevent a background launch.

### F3 — The CLI rejects the conventional pnpm argument separator

- **Evidence:** after the schema retry, turn 1 seq 141–143 successfully spawned `pnpm start -- --yolo…`, but reading its output at seq 144–146 revealed `error: Unknown argument "--"` and exit code 2. Removing the separator in the corrected launch at seq 147–149 started the real worker. The final answer acknowledges this deterministic pre-launch failure (seq 1096).
- **Root-cause area:** other
- **Suggestion:** normalize one leading standalone `--` in Darwin's CLI argv before command parsing, so both `pnpm start --yolo…` and the conventional `pnpm start -- --yolo…` reach identical validated arguments; cover both forms with a no-model CLI test.

### F4 — Exact replacement failures do not diagnose whitespace-near matches

- **Evidence:** turn 1 seq 107–109 failed because an otherwise matching backlog row had a different trailing-newline count. The error repeated the absent string but did not identify the whitespace-only mismatch; Darwin then needed a byte dump and a raw `truncate -s -1` workaround (seq 110–115).
- **Root-cause area:** tool description
- **Suggestion:** on a `fileEditor.str_replace` miss, return a bounded whitespace-visible diagnostic for the closest exact-prefix/suffix candidate, without performing a fuzzy edit, so the model can issue a safe corrected replacement instead of reaching for byte-level shell mutation.

### F5 — Supervision repeats full gates when source inputs have not changed

- **Evidence:** the Host ran `pnpm typecheck`/`pnpm test` before committing the research artifacts (turn 1, seq 98–106) and ran them again immediately after the docs-only batch commit (seq 122–130). Later it correctly reran full acceptance after each implementation (for example seq 555–577 and the SER-030 acceptance stretch ending before seq 1075). The first duplicate pair added roughly 98 seconds each while no source implementation changed.
- **Root-cause area:** execution time
- **Suggestion:** teach the developer supervision workflow to key baseline results to the tested source-tree hash and reuse them only across docs-only Host commits, while always rerunning the independent acceptance gate after a child implementation or any source/config/test change.
