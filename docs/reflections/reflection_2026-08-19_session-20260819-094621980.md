## 4. Improvement findings for darwin

### F1 — Background-child supervision consumes excessive model rounds on empty polling

- **Evidence:** turn 1 made 322 child-monitor calls: 112 `output` and 113 `status` calls for `bg-1d88…` (seq 61–745), then 48 of each for `bg-3349…` (seq 842–1127). The turn consequently recorded 390 tool calls, 1,619,505 ms, 29,053 output tokens, and 109,561,787 cache-read tokens (turn 1 / seq 1176), even though only two children completed.
- **Root-cause area:** orchestration / execution time / token spend
- **Suggestion:** add a blocking `bash` background wait operation (or `status` with a bounded `waitMs`) that returns on state change, completion, or timeout and includes incremental output, so a supervising model can wait once per interval rather than spend a new model round alternating `status` and `output`.

### F2 — The bash tool reports successful commands as errors when the persistent shell exits

- **Evidence:** five SRF-002 acceptance calls returned the exact error `Error: Bash process exited unexpectedly with code 0` (turn 1 / seq 1145–1155), including `pnpm typecheck`, `pnpm test`, the focused suite, and Trellis validation. Their logs later showed 72 focused checks and 51 test summaries passed, and a separate summary call succeeded (turn 1 / seq 1157–1158). This forced redundant verification and made green results look failed.
- **Root-cause area:** tool description / other (bash execution semantics)
- **Suggestion:** change the bash execution manager to treat process exit code 0 as success even when the persistent shell closes unexpectedly, returning captured stdout/stderr plus a non-fatal shell-restart notice; add a regression case covering parallel foreground calls racing a shell restart.

### F3 — Early schema and launch-shape mistakes cost avoidable retries

- **Evidence:** `fileEditor` rejected an otherwise valid view because the requested end line exceeded the file length (turn 1 / seq 39–40), and `bash start` rejected a copied `timeout` field before the child could launch (turn 1 / seq 48–49). Darwin then made two more launch attempts before obtaining the successful SRF-001 task (turn 1 / seq 51–61).
- **Root-cause area:** tool description
- **Suggestion:** make `fileEditor view` clamp an oversized positive end line to EOF, and expose mode-specific bash input shapes in the generated tool description so `start` does not present or invite the foreground-only `timeout` field.
