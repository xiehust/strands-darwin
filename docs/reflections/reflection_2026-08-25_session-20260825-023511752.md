## 4. Improvement findings for darwin

### F1 — Stop repeated speculative retries when the failure signature does not change

- **Evidence:** The first recommendation run established a stable service-side validation failure (turn 2 / seq 169–182). Darwin then spent the remainder of the turn researching and launching multiple altered variants—failure-case, combined sessions, ten sessions, duration changes, generic scope, and a root span—without recording a successful artifact (turn 2 / seq 186–341); the turn consumed 726,771 ms and 11,483 output tokens before cancellation (turn 2 / seq 343).
- **Root-cause area:** execution time
- **Suggestion:** Add a bounded repeated-failure guard to Darwin’s system guidance and tool-loop state: fingerprint normalized tool/command failures, require each retry to state a materially new evidence-backed hypothesis, and after three unsuccessful variants with the same failure class stop retrying and report the blocker plus collected artifacts unless the user explicitly asks to continue.

### F2 — Preflight CodeGraph availability before treating it as the primary repository reader

- **Evidence:** Darwin called `codegraph_explore` without a resolved workspace and received `No CodeGraph project is loaded`; it retried with `projectPath` and received `CodeGraph not initialized` (turn 1 / seq 45–49), then fell back to shell reads. Both calls were avoidable capability probes embedded in the task path.
- **Root-cause area:** tool description
- **Suggestion:** Extend CodeGraph tool routing so Darwin checks index availability once (or the tool performs this preflight internally) and immediately chooses shell/file inspection when `.codegraph` is absent, rather than retrying an uninitialized project.

### F3 — Treat zero-result web search as an empty result, not a tool-use error

- **Evidence:** An exact-site search returned an error solely because the upstream tool found no results—`Tool returned no results` (turn 2 / seq 304–305)—although “no matches” is a normal search outcome and Darwin simply continued with other sources.
- **Root-cause area:** tool description
- **Suggestion:** Change the web-search adapter contract to return a successful empty result set with the query preserved, reserving error status for transport or service failures, so normal absence does not pollute failure accounting or prompt unnecessary recovery behavior.
