## 4. Improvement findings for darwin

### F1 — Distinguish the existing-file size ceiling from the tool-call payload bound

- **Evidence:** The file was already reported as 3,679,335 bytes (turn 3 / seq 112), yet the assistant later attempted a short `str_replace` on that same HTML (turn 5 / seq 273). The error named the 1,048,576-byte ceiling (seq 274). Reading and editing the much smaller generator provided a successful route without clobbering unexpected HTML changes (seq 280, 285–286, 309).
- **Root-cause area:** Tool description. At Darwin baseline `8f27abdeabf8881e7cb781c13c9a4640bbde872b`, `src/tools/file-editor-serial.ts:37–45` appends `FILE_EDITOR_PAYLOAD_GUIDANCE` to the SDK default description. It warns about oversized emitted payloads but says nothing about the size of the file already on disk. The installed pinned SDK's `file-editor.js` defines `DEFAULT_MAX_FILE_SIZE = 1048576`; `handleView`, `handleStrReplace` and `handleInsert` call `assertWithinSizeLimit` on the whole existing content, before view slicing or replacement. `handleCreate` does not share that assertion. This is a different limitation from SRF-032's long-output/stream guidance, not an argument for increasing a cap.
- **Suggestion:** Extend the description supplied to `makeFileEditor` with the exact 1 MiB UTF-8 existing-file limit for `view`, `str_replace` and `insert`, explicitly distinguishing it from per-call payload size. Tell the model not to retry a known-over-limit file with smaller ranges or strings. For generated output, prefer an already-inspected, authorized source/generator change and normal regeneration only when unexpected output edits are protected; otherwise report the limit rather than silently switching mutation channels. Preserve the wrapper projection, limits, schema, permissions and error bytes. Add parent/child description assertions and real-file boundary/zero-write checks. This is queued as SRF-040.

### F2 — Persistent cwd still needs to inform subsequent root-relative reads

- **Evidence:** A foreground discovery command ended with `cd frontend` (turn 2 / seq 48, result seq 57). The next root-relative `cat` was run from that retained directory and failed; its structured result truthfully named cwd (seq 50, 58). An absolute `cd` repaired the read (seq 70).
- **Root-cause area:** Execution context / tool guidance. Existing SRF-014, Priority 52, is already `done`: it exposes effective cwd and conservatively preflights narrow relative command-path mistakes. Its documented exclusions leave ordinary PATH commands and complex syntax alone; this `cat` command is not proof that the existing implementation regressed. Re-enqueuing cwd exposure or general root-relative preflight would duplicate that direction.
- **Suggestion:** Use the existing SRF-014 cwd result when forming the next command, and issue an explicit project-root `cd` or absolute paths for repository-root reads after changing directories. Retain its conservative preflight and regression coverage rather than guessing arbitrary shell path arguments or resetting cwd globally. Treat this as recurrence evidence for SRF-014, not a new queued direction.

### F3 — A generic terminated stream is not yet a safe automatic-continuation predicate

- **Evidence:** The model failed with `ModelError: terminated`, cause name `TypeError`, after successful file creations (turn 2 / seq 95–97). The user explicitly requested continuation (turn 3 / seq 98), after which work completed (seq 249; turn 4 / seq 254). The visible failure does not include the exact interruption message covered by SRF-001.
- **Root-cause area:** Orchestration / execution time. `src/agent/stream-resumption.ts:20–24` matches only `Stream ended without completing a message`; its retained-conversation continuation deliberately avoids replaying completed side effects. The observed error is outside that predicate. A five-minute gap is not evidence of why the provider terminated or whether another call would be safe.
- **Suggestion:** The candidate change would add `ModelError: terminated` with cause `TypeError` to the driver's one-continuation predicate. Reject that expansion for now: the generic signature is insufficient, and replay safety is not established by this run. Keep manual continuation and the existing exact predicate until a provider-specific, cancellable and side-effect-safe condition can be demonstrated. No implementation of this candidate is queued.
