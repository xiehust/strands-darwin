## 4. Improvement findings for darwin

### F1 — Prevent an internal working note from becoming a successful final turn

- **Evidence:** The user asked for a completion check (turn 6 / seq 381). After all checks passed, Darwin emitted only a private-style note—“Need answer in Chinese” and “Update plan”—which itself says the work is complete (turn 6 / seq 436). The SDK then produced `agentResultEvent.stopReason: endTurn` and a normal `turnEnded`, with no failure, cancellation, or limit marker (turn 6 / seq 437–438). The same pattern occurred one turn earlier: an internal “Need continue tools” note became the last message and returned control without starting the stated work (turn 5 / seq 378–380).
- **Root-cause area:** orchestration
- **Suggestion:** Add a pre-`endTurn` completion guard in Darwin's parent loop: classify the candidate final text for internal-work markers (for example, first-person TODOs such as “Need …”, “Update plan”, tool-intent statements, or explicit declarations that a user answer still must be written). If matched, suppress that candidate from the user-visible final result and run one bounded continuation prompt requiring either the promised tool call or a concise user-facing answer; record the guard and cap it at one retry to avoid loops.

### F2 — Make persistent-shell working-directory state visible before relative commands run

- **Evidence:** A command expected the repository root but inherited `backend`, causing `cd backend: No such file or directory` (turn 4 / seq 249–250); `./start.py --help` then failed for the same reason (turn 4 / seq 258–259); and the later i18n command looked for `scripts/i18n_check.py` under `backend` (turn 5 / seq 374–377). These were avoidable orchestration errors caused by hidden persistent-shell state rather than project defects.
- **Root-cause area:** tool description
- **Suggestion:** Include the shell's effective cwd in every bash result and add a tool-description warning that `execute` reuses the persistent shell's cwd. For a relative command whose first path segment does not exist in the effective cwd but does exist under the session project root, return a non-mutating preflight diagnostic naming both paths instead of launching the command blindly.

### F3 — Surface progress during long blocking subagent calls

- **Evidence:** The implementation subagent call blocked for 4,266.641 seconds with no intermediate parent-side event (turn 4 / seq 150–151); two more subagent calls blocked for 775.998 and 1,168.480 seconds (turn 4 / seq 155–160). Turn 4 consequently lasted 6,701,090 ms and consumed cacheRead=12442410 (turn 4 / seq 367). From the user's perspective, this extended silence is another plausible source of the impression that the task stopped, even though the record later shows successful child returns.
- **Root-cause area:** execution time
- **Suggestion:** Extend the subagent tool with bounded progress events: emit a heartbeat at least every 30 seconds containing elapsed time, current child phase/tool name when available, and a cancellable task id, while preserving the existing final result contract and avoiding child reasoning leakage.
