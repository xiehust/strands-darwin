### Peer highlights and innovations

| Product | Sourced feature / innovation | Reference | Why it matters |
|---|---|---|---|
| Claude Code | **One command queue for everything addressed to an agent** — typed prompts, `!`/slash commands and task-notifications share one store, one priority scale and one drain; notifications are just another entry (`mode: "task-notification"`). | S1, S2, S8 | A finished background task needs no second channel into the model: it is delivered the same way a user prompt is. |
| Claude Code | **Two consumption paths keyed on agent state.** Mid-turn: the loop folds queued entries into the running turn at tool-result boundaries. Idle: a UI-layer effect drains the queue and starts a turn with no user prompt (“the model is woken”). | S1, S3 | Background subagent/bash completion never holds the turn open; the parent ends its turn, the user keeps talking, and the result arrives as a later turn. |
| Claude Code | **Per-task `notified` test-and-set on an in-memory registry**, addressed to the owning agent; resume re-registers and re-arms. | S2 | Exactly-once intent, but implemented as a flag race — the two headline bugs (lost reply, permanent idle stall) come from it and from the drain having no retry. |
| Claude Code | Foreground Bash exceeding its timeout is **converted into a background task** and enters the same notification machinery. | S4 | Darwin's `exit 0 returns captured output + restart notice` foreground contract is the deliberate opposite; noted, not adopted. |
| Claude Code (failure modes) | Premature/duplicate notifications (fires on stdout, re-fires per turn-end), notification-driven turns invisible to hooks, no opt-out, decoupled from `TaskOutput`, killed on subagent return, undeliverable to an ended agent. | S4, S5, S6 | Each one is a constraint darwin can write into the requirement up front: fire on exit only, exactly once, observable, cancellable, owned by the session not the dispatching child. |

### Areas inspected and left alone

- **Mid-turn injection of completions** (Claude Code's fold): rejected — SER-027's next-turn-only contract is what users of the peer ask for, and darwin's trajectory/replay reducers assume one turn per `send()`.
- **Snapshot/rewind with tracked tasks**: the SDK refuses `assertCanLoadSnapshot` while tasks are tracked. With `waitForCompletion: false` a `/rewind` during a live background child would hit this. The record requires a local refusal notice, not a design change to rewind.
- **A second `wait`-style blocking tool for delegations** (`TaskOutput(block:true)` analogue): the SDK's `strands_manage_background_task` already offers `get`; a blocking form is unnecessary once completions wake the agent.
