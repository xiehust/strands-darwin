### Recommendation

- Batch: **SER-126**, priority **166**, appended to `backlog/directions-161-180.md`. No rollover or index mutation. Select only after a clean, passing HEAD; recheck the unchanged score 13 against gate 6.
- Requirement: exact case-insensitive `/review` name with case-sensitive leading `--base` and one full 40-hex SHA. Preserve SHA bytes; reject missing/short/nonhex/extra/combined/equals-form scope input locally, before queue/model work. `--baseish` and ordinary focus remain literal; existing bare/focus/commit behavior and commit usage remain unchanged. A separate base usage message must reach every driver, not the old commit-only message.
- Prompt contract: resolve the supplied exact commit and HEAD as commit objects, identify/report their actual SHAs and **unique merge base**, review only the committed merge-base-to-HEAD diff with surrounding code/tests from that scope, explicitly exclude staged/unstaged/untracked edits. If objects/HEAD are unavailable, histories unrelated, or multiple merge bases exist, state the limitation and stop rather than choose a base, fetch, checkout, or invent findings. Empty diff is stated honestly. Prioritized actionable file/line findings, separate test gaps, no speculative/style-only findings, honest unverified limits/tests not run, and no edits/commits. Guidance only: never claim enforced read-only or guaranteed model behavior.
- Extension points: pure `src/commands/review-command.ts`, existing `AgentRuntime.expandSlashCommand` and TUI/headless/dev-repl local usage paths. No new tool, Git executor, subagent, permission mode, network, dependency, SDK patch, config or session format.
- Acceptance checklist: parser byte-preservation/negative grammar and fixed semantic clauses; real runtime text/JSON/JSONL expansion and literal trajectory; malformed base requests make no model/permission/queue call and preserve TUI draft/image while busy; valid queued base review delivers exactly once with its attachment; dev-repl parity; existing commit/focus and gate regressions; all built-ins remain discoverable. Use `spike/verify-review-command.ts`, `spike/verify-review-drivers.ts`, free `spike/verify-tui.ts completion`, `pnpm typecheck`, `pnpm test`, and `pnpm build`. These verify the harness contract, not live review accuracy.
- Documentation: both READMEs, English/Chinese narrative and reference user-guide pages, architecture review paragraphs. Explain that users resolve their chosen base to a full SHA first and HEAD is resolved by the reviewing model at inspection time, not pinned by the slash parser.
- Authorization: fresh developer child may edit implementation, focused tests and corresponding docs, run offline checks and commit. Host owns research/backlog/iteration-log, independent acceptance, build and final push. No dependency changes, release bump, destructive Git, configuration/permission policy changes, or recursive supervision. Unresolved decisions must return to the Host/user.
