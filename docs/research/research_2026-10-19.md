### Comparison and gaps

1. **Next-prompt assistance (S1 versus R2):** after reading an answer, the user currently has to compose the next request manually or recall prior input. The proposed feature offers one context-relevant candidate; Right arrow places it in the draft without sending. Ordinary editing and explicit Enter still control the next turn. Initial-session examples drawn from Git history are excluded from this direction.
2. **Away-return orientation (S1–S2 versus R1):** startup replay restores history, but a user switching back to an already-running terminal does not receive a short summary of where the session stands. A separate recap may provide that without mutating context or shortening history. It is not an every-turn conclusion or automatic `/compact`.
3. **Cost/default decision (S1 versus R3):** both features introduce auxiliary inference. Claude's suggestion cache behavior cannot be promised for Darwin's provider-neutral implementation. The user must choose default-on with off switches versus opt-in before implementation; neither an existing classifier side call nor the example's mention silently settles that product policy.
