### Comparison and gaps

| Peer evidence | Darwin evidence | Parity / gap / deliberate difference | Implication |
|---|---|---|---|
| Claude/Codex/Windsurf automatically distill learnings into persistent text | Darwin stores raw trajectory only | **Core gap** | Add a derived, inspectable Markdown memory layer produced from closed sessions, not a transcript-search tool. |
| Claude loads a compact notebook at startup; Windsurf retrieves memories when relevant | Darwin startup has no learned-context block | **Gap** | MVP should load a small project memory index automatically; topic detail remains on-demand through existing file/text reads. No vector retrieval is needed. |
| Cursor/Windsurf expose memories for management | Darwin has no memory UX | **Gap** | Add `/memory` list/show/forget (and explicit user “remember” path only if scoped safely); every learned item needs provenance and edit/delete affordance. |
| Codex skips active/short sessions and updates asynchronously | Darwin records active input before invocation | **Important deliberate constraint** | Mine only closed successful turns after the user-visible turn is complete, outside the stream, and never block or fail the turn. Batch/delay extraction rather than run on every token or active session. |
| Codex redacts secrets | Trajectories may contain prompts/tool input/results | **Safety gap** | Generated memory fields need secret filtering and must never retain reasoning, credentials, `.env` values, tokens or arbitrary large tool output. Ambiguous sensitive candidates are dropped. |
| Copilot validates current code and expires stale facts | Darwin facts could outlive code changes indefinitely | **Correctness gap** | Store source references and freshness metadata; code-derived facts require revalidation before startup inclusion, with stale/invalid facts omitted and visible to `/memory`. User preferences may have different retention. |
| DeepSeek keeps a canonical event stream and uses plugins | Darwin has trajectory + thin SDK extension seams | **Strong architecture fit** | Memory is a derived session-scoped service/plugin fed by the trajectory after closure; trajectory bytes remain unchanged and authoritative only as evidence. |
| All mature designs separate instructions/rules from memories | Darwin has AGENTS.md/skills | **Must preserve** | Memories are bounded context labelled as learned and fallible. They cannot override AGENTS/project instructions, permissions, hooks or user text. |
