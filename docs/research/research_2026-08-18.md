### Recommendation

- Batch to implement: `SER-013`, `SER-014`, `SER-015`
- Start with: `SER-013`
- Why this order: score order, and it is also the safety order. `SER-013` is the only one of the three
  that touches enforcement, so it should land while the tree is otherwise unchanged and be accepted on
  its own evidence. `SER-014` and `SER-015` then both edit the prompt/completion surface, and doing the
  new completion *source* before the new `Up`/`Down` *binding* means the second iteration can see the
  final menu behaviour instead of guessing at it. There are no hard dependencies, so no score override
  is claimed.
- Independently observable acceptance:
  - **SER-013** — the effective mode is switchable mid-session from the user's own input and from
    nowhere else (a model-driven attempt changes nothing and is refused); every mode transition is
    reflected in the existing header row without adding a frame row (`verify-tui.ts approve`, 50 rows);
    with `plan` selected mid-session, a subsequent write/execute is denied before hooks, allow-rules,
    the `auto` classifier and the bridge, for parent *and* child agents, exactly as
    `verify-permission-modes.ts` already asserts for startup plan; leaving `plan` mid-session lets a
    write proceed through the ordinary gate; a prompt queued or a classifier check in flight when the
    mode changes is never resolved under a mode that would not have asked for it; the change is
    session-scoped and writes nothing to `~/.darwin/config.json`; `pnpm typecheck`, `pnpm test`, the
    focused permission suites, a real-pty scenario, `git diff --check` and Trellis validation pass.
  - **SER-014** — typing `@` offers bounded path completions, accepting one inserts the path text and
    nothing else, no file content is read or injected by the completion itself, the menu obeys
    `MAX_COMPLETIONS`/frame-budget rules with counted heights, `.git`/`node_modules`-class directories
    and symlink escapes are excluded, a large tree neither stalls the editor nor overflows the frame,
    and the existing `/` completion behaviour is unchanged (`verify-tui.ts completion` still passes with
    every built-in visible).
  - **SER-015** — recall returns previous prompts of *this project* newest-first with consecutive
    duplicates collapsed; it never fires while a completion menu is open and never replaces multi-row
    cursor movement; a session recorded with `trajectory: false` degrades to "no history" rather than an
    error; recall performs no model call and no network access; and existing prompt-editor, cursor and
    multiline suites stay green.
- Backlog updates: add `SER-013`, `SER-014`, `SER-015` as `not-started` at priorities 13, 14, 15; no
  existing row changes status by the gate. `SER-012` was closed to `done` *before* this research, on
  independent evidence recorded in its row. Change exactly one direction to `in-progress` immediately
  before each developer handoff.
