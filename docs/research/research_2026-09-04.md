### Current Darwin baseline

| Capability / architecture | Repository evidence | Current behavior |
|---|---|---|
| Model retry policy | R1, R2, R3 | Darwin constructs `Agent` without `retryStrategy`, inheriting `DefaultModelRetryStrategy`: up to 6 attempts, exponential backoff 4 s base / 240 s cap / full jitter, retryable set = `ModelThrottledError` only. Darwin has no module, config key, test or doc mentioning it (`grep -rn retryStrategy src spike docs` → nothing) |
| What the driver sees during a retry wait | R3, R5 | Nothing. The sleep runs inside the hook before the event reaches `AgentRuntime.send()`'s consumer; the TUI keeps `thinking… · 0:07` (R6), headless emits no event, and the failed attempt is only visible afterwards as a gap in `modelCall.attempt` numbers (R6) |
| Esc / Ctrl+C during a retry wait | R1, R2, R5 | `runtime.cancel()` → `agent.cancel()` aborts the SDK signal, but the strategy's `setTimeout` sleep does not listen to it: the cancel takes effect only after the remaining backoff (measured 1.6 s in the probe; up to ~64 s after the fifth throttle with the default schedule), and the loop then issues one more model call before settling `cancelled` |
| Bedrock pre-stream throttling | R4 | The common Bedrock 429 (`ThrottlingException` from `ConverseStream` before any stream event) is a plain `ModelError` to the Strands loop → **not retried**; the turn fails at once with `turn failed: Too many requests…` (R6) and the user must resend. In-stream throttling *is* retried (silently, see above). Anthropic and OpenAI 429s are retried |
| Existing darwin `AfterModelCallEvent` hook precedent | R1 | `installMaxTokensRecovery` registers an `AfterModelCallEvent` hook via `agent.addHook`, inspects `event.error` and `event.agent.cancelSignal.aborted`, and acts through SDK-designed event fields — the exact shape a darwin-owned retry hook would take |
| Stream-interruption continuation | R7 | Deliberate: only the exact `Stream ended without completing a message` text gets a visible successor *turn*; it explicitly forbids an SDK-loop retry for that case. It says nothing about throttling, which the SDK already retries inside the loop today |
| Subagents | `src/agents/child-recipe.ts` (`new Agent({...})`, no `retryStrategy`), `src/agents/subagent-tool.ts` (cancel via `context.agent.cancelSignal`), `dispatch-registry.ts` `setPhase` | Children inherit the same default strategy; `/agents cancel <id>` suffers the same delayed cancel during a child's backoff; the heartbeat's safe phase vocabulary has no "throttled/waiting" state |
