### Recommendation

- Batch: **SER-124**, Priority **164**, in `backlog/directions-161-180.md`; no rollover or index summary.
- Requirement: recognize a one-shot **Ctrl+X then Ctrl+E** composer chord, both separate input events and a combined terminal write. It must call the existing `openExternalEditor`, with no second handoff mechanism. Ctrl+X alone does nothing to the draft; an intervening different key clears the prefix and retains that key's normal behavior. Repeated Ctrl+X may re-arm one pending prefix. There is no timer, new frame row, persistent state, or automatic submission.
- Safety: the prefix cannot survive permission/search/compaction ownership, paste, submission/queueing, session replacement or another editor handoff. Never arm under a higher-priority owner. The second chord is subject to the same current-state eligibility checks as Ctrl+G, including busy/queue/delegation/peer/goal refusal and editor-active fencing. Bare Ctrl+E stays row-end; Ctrl+G stays unchanged.
- Acceptance: derive a requirement-to-test checklist; real production-CLI pty proof of separate and combined chord, exact multiline draft round trip, one launch and no provider/trajectory prompt before explicit Enter; cancellation/failure preserve draft; prefix invalidation and modal/async transitions; unprefixed Ctrl+E and Ctrl+G regressions; existing editor security/cap/cleanup suites. Run `pnpm typecheck`, `pnpm test`, affected focused editor/input/help suites, free `tui completion`, and `pnpm build`.
- Documentation: keep `/help`, both READMEs, English/Chinese narrative/reference guides and the existing editor architecture heading in step. No new slash command or SDK invariant.
- Authorized implementation: relevant `src/tui`, real `spike` tests, associated user/architecture docs and test registration if needed; commit locally. No new dependency, SDK-loop/patch rewrite, policy/config/credential change, external service mutation, auto-submit or publish. Host owns research/backlog/iteration-log records and the final push. Developer skill loaded once; fresh source-CLI child only after a clean green starting gate.
