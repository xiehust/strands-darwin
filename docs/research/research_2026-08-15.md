| Permission provenance | [`AssessedPermissionRequest`](../../src/agent/permission.ts), [`PermissionPrompt`](../../src/tui/PermissionPrompt.tsx) | The request carries `toolName`, `kind`, risk and rule suggestions — but nothing about *who* asked. | Prompt serialization | [`PermissionQueue`](../../src/tui/permission-queue.ts) | Requests are answered strictly one at a time. That stays correct under parallelism, but ownership of the current prompt becomes ambiguous without a source label. |
| Live/finished rendering | [`ActiveTool` / `HistoryItem`](../../src/tui/turn-state.ts) | Neither carries an originating agent, so concurrent child work cannot be told apart on screen. |
| Comparable existing pattern | background jobs: `runtime.listBackgroundTasks()` / `subscribeToBackgroundTasks()` and the `/tasks` contract in [`tui-testing.md`](../../.trellis/spec/frontend/tui-testing.md) | Darwin already has an accepted shape for observing concurrent work: a manager the runtime exposes, an observer-only subscription, and a bounded presentation-time projection. |
