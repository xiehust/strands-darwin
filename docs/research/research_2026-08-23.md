### Peer highlights and innovations

| Product | Sourced feature / innovation | Reference | Why it matters |

| Codex | Work-plan tracking is explicitly separate from read-only Plan Mode, and parallel subagents are recommended first for read-heavy work. | S2, S3 | Darwin should not confuse its enforced permission mode with execution progress; its existing read-heavy subagent policy already matches the parallelism guidance. |

### Comparison and gaps

| Peer evidence | Darwin evidence | Parity / gap / deliberate difference | Implication |
|---|---|---|---|
| Claude, Codex, DeepSeek, and OpenCode all expose model-authored structured work progress (S1, S2, S4, S5, S8) | Runtime catalogue and TUI have no plan store or checklist | **Gap** | Add one parent-agent progress tool and one bounded live projection, while retaining ordinary tool-event recording. |
| DeepSeek keeps todo state out of ordinary conversation nodes but makes it replayable (S4, S5) | Darwin trajectory records before/after tool events and replay already renders tool rows | **Strong fit with a deliberate simplification** | Use the existing tool call/result as durable evidence; do not invent a trajectory record type or make the checklist authoritative session data. During the turn show the latest list; commit the final bounded list to Static history at turn end. |
| OpenCode says completion follows actual verification (S8) | Darwin's project instructions require verification before claiming success | **Parity in policy, missing enforceable shape** | Tool guidance and tests should preserve status vocabulary and reject malformed/duplicate/unbounded lists, but cannot pretend to verify a model's claim automatically. |
| DeepSeek detaches subagents behind generic jobs (S6) | Darwin has generic background *bash* controls but synchronous subagent tool calls | **Real gap, high coupling** | Do not bolt `background: true` onto subagents until ownership, result injection, cancellation, `/clear`, and generic non-process task controls have one design. |
| The installed Strands SDK supports interrupt/resume, and peer plan experiences can solicit decisions | Darwin accepts only string turns and currently treats interruption/cancel/continuation very specifically | **Unused SDK capability with unresolved protocol cost** | A general question modal is promising, but it needs a separate contract for headless refusal, queue ownership, trajectory turn outcomes, resume snapshots, and several simultaneous tool interrupts. |
| Penguin advertises benchmark-driven self-evolution plus Trace (S7) | Darwin has append-only trajectory, independent Host acceptance, Trellis task history and iteration log | **Substantial parity / deliberate difference** | No new evaluation direction is justified from unpublished benchmark claims; revisit only with a public reproducible corpus or Darwin-specific failure evidence. |
